### What's new

#### Re-take a page, in place

The review now offers **Re-take** on any page: tap it, shoot again, and the new shot takes the
place the old one held. The page keeps its position in the document, and the run carries on from
there.

Before this, the only way to fix a page was to delete it and shoot another, which appends at the
end and leaves you to drag it back to where it belongs — and on a long document, that is the
whole job. The re-take exists to remove that detour.

Three things were true before it was written, and each is why it looks the way it does:

- **Nothing is written until the shot arrives.** Re-take is a prompt, not an edit. If you leave
  the camera without shooting, the page is exactly as it was.
- **It arms exactly one shot.** The prompt is shown on screen — *"Re-take page 3"* — with a way to
  cancel it, and the shot after that appends like any other. Changing the mode or the Batch
  setting drops the prompt, because the page a re-take would replace is a property of the run it
  was started in.
- **A failed re-take must not cost you the page.** The replacement's pixels are written first,
  and the row swap — insert the new, delete the old — is a single database transaction. If the
  write fails, it rolls back and the original page, and its files, are still there. The old files
  are deleted only after the swap succeeds.

Re-take is offered where one shot means exactly one page: **Single with Batch on**. It is not
offered for a book spread, where one shot becomes two pages, or for a card, where two shots become
one — "replace this page with one shot" has no single answer there.

#### New captures landed in the middle of the document

Fixed. The index for a new page was derived from *how many rows the document holds*, which is not
the same question as *which slots are in use*. A document holding indices 0, 1 and 2 that loses
the page at 1 still has 2 in use, but a count says two rows remain — so the next capture was
written to index 2, ahead of the page already sitting there. Any delete left the document in that
state, and a re-take would have made it routine.

The next index now comes from the highest index in use, one past it. That is what keeps a
replaced page in its own slot while everything captured afterwards still lands at the end.

#### Batch is a toggle, not a mode

Batch used to be a fourth mode, which made "a book spread, captured once" impossible to express:
choosing Book meant shooting spread after spread for ever, choosing Batch meant single pages only.
Whether the camera keeps going is not a property of what one shot becomes, so it is now a switch
of its own, sitting beside the three shapes on the camera row and labelled plainly in Settings.

- **Single** — one shot. Batch off hands it to the editor for manual corner placement; Batch on
  appends it and keeps the camera ready.
- **Book** — one spread becomes two pages, once or repeatedly.
- **ID card** — front and back become one sheet, once or repeatedly.

Anyone who used the old **Batch** mode gets Single with the toggle on, which is the same behaviour
under a new name. Book and ID-card users keep the continuous capture they had. Nothing to set up,
and the old choice is not silently discarded.

### Also in this release

- A **Batch** chip beside the mode chips, coloured as a switch rather than as a mode, so it does
  not read as a fourth shape.
- The hint under the shutter describes what happens next in the mode's own terms — *"Page after
  page"* for Single with Batch on, rather than the editor hint that no longer applies.
- The page strip and the **Done** button appear only for the runs that keep going, so a single
  shot to the editor no longer carries controls that do nothing.
- Settings has a single line for it: **"Keep shooting into one document"**, with what it does
  spelled out underneath.

### Known issues

- Folder support is unreachable end to end. No code assigns a document to a folder — every
  document is created with a null folder — so the folder filter never appears at all; and if one
  ever did, the row would only ever show three folders.
- Rename works on one document at a time: with more than one selected the Rename action is not
  offered at all. Bulk delete is correct.
- In the editor, **Detect** discards a manual rotation: re-running detection resets the corners
  to the detected quad.
- Rotating a page does not invalidate the stored OCR line boxes, so text selection on a rotated
  page can still point at the pre-rotation positions.
- `sweepCaptures`, the cleanup of stale capture files, is written but not called from anywhere.
