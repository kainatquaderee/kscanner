### What's fixed

#### The framing border is drawn on the page

Point the camera at a page and v1.6.0 drew the border somewhere else. It arrived at a fraction of
the page's size, off to one side, with its right-hand edge running past the edge of the screen —
and the dimmed area covered the wrong part of the picture, which is the same mistake seen from the
other end. There was nothing to line the page up against, because the border was not where the page
was.

The border was the detector's real answer to the real page. What we had wrong was the ruler it was
reported in. Detection runs on a small grayscale copy of each frame — half-size at the 640x480 the
analyser asks the camera for, and smaller still on a device that hands over a bigger frame — so the
detector's corners are in that copy's pixels. We told the drawing side the camera's full size
instead, and the same numbers read against a frame twice as large are a border drawn at half scale
about the wrong centre. A quarter turn made it worse: turning the corners mirrors them about the
frame's height, so the error pushed the border sideways as well as inward, which is why it ended up
hugging the edge of the screen rather than sitting small in the middle of it.

We now produce the copy and the description of it together, as one value, so they cannot disagree:
the frame the border is drawn in is the frame that was actually searched.

### Also in this release

- **Nothing else changes.** The automatic shutter, the five-pixel deadband, the easing between
  positions, the wait before the border is dropped and the confidence gate are untouched. No setting
  appears or disappears, and what a shot captures is exactly what it captured in v1.6.0.
- The border still slides rather than snaps, still refuses to draw an outline it is less than 0.45
  sure of, still uses only the line detector live, and still clears itself about a third of a second
  after the page stops being found.
- Two tests now hold this down. One photographs a page into a camera-sized frame, samples it the way
  the analyser does, detects it, and checks the border lands on the page at each of the four
  rotations a camera can report. The other pins the size of the error the old bookkeeping caused, so
  that going back to it fails loudly instead of quietly drawing in the wrong place.

### Known issues

- **The live outline is found on a subsampled frame.** The preview's grayscale image is made small
  for detection by skipping pixels rather than averaging them, so the detector sees a slightly more
  aliased picture here than it does on a photograph you import. On a busy background that can cost
  the live border confidence that a still shot keeps.
- **A border can run off the screen.** The preview fills the screen by cropping the frame, so when
  the page reaches the frame's sides — which is what happens when it fills your view — the part of
  the border tracing those sides is drawn outside the visible area. It marks where the page really
  is, but on a tall phone it can read as two lines rather than a frame.
- Folder support is unreachable end to end. No code assigns a document to a folder — every
  document is created with a null folder — so the folder filter never appears at all.
- Rename works on one document at a time: with more than one selected the Rename action is not
  offered at all. Bulk delete is correct.
- In the editor, **Detect** discards a manual rotation: re-running detection resets the corners
  to the detected quad.
- Rotating a page does not invalidate the stored OCR line boxes, so text selection on a rotated
  page can still point at the pre-rotation positions.
- `sweepCaptures`, the cleanup of stale capture files, is written but not called from anywhere.
