### What's new

#### Correct a page you already have, and give its look to the rest

Until now the viewer could only ever add to a document: a page shot again, a filter changed, a
strip of text recognised — never a correction to a page the document already held. A page could be
looked at, but not put right.

**Edit** now sits in the viewer's action row. It acts on the page the viewer is *showing* — the one
on screen, not the one the document was opened with — and it opens the editor on its look stage
with that page's own filter, strength and crop loaded from its row, so what comes up is what is on
the page. Save rewrites that page where it is: the same position in the document, the same file,
new pixels behind it. A page corrected this way is never appended as a second copy of itself.

**Apply to all** sits beside **Save page**. It names how many pages it will touch before it starts
(*"Apply this look to the other 2 pages?"*), shows progress page by page, can be stopped between
pages, and reports what it did — *"The look was applied to 2 pages."* — with a way to go and look at
them. The page being edited is never among its targets, because it already has the look.

What a page carries is now a thing in its own right: the preset, its strength, and brightness,
contrast, sharpness and deskew angle travel together as the page's look, and are stored with it. A
rotation or a turn-over keeps all of it, where before they re-rendered from the geometry alone and
dropped it — the 180° turn that grew a 2.6 MB page to 2.7 MB was losing exactly that.

#### Turn a page over in one action

A page shot upside down needs two quarter turns, and the only way to ask for that was to press
rotate twice: easy to overshoot, and the wrong gesture for a page that simply arrived that way. The
review overlay has always offered the turn as one action, so the same glyph and the same wording now
appear where a page is looked at after the fact — beside **Rotate** in the viewer, and in the page
sheet next to rotate left and right. Both go through the same rotation path, so the outline, the
stored rotation and the rendered file stay consistent.

#### A single page shot in Book mode stays one page

Book mode cut every shot at its darkest column and committed both halves, so a photograph of *one*
page came out as two half-pages with the text sliced down the middle — and nothing in the app can
join them, so the only cure was to delete both and shoot again.

The split is now decided by the questions that actually separate a crease from a block of ink: the
dark run has to be narrow, dark on every row of its own height taken row by row, and the paper
immediately either side of it has to be brighter — measured separately, so a shadow falling over one
half cannot pass for a gutter. Short of all three, the shot is one page. That is the failure you can
see and shoot again, where two halves cannot be rejoined.

Book mode also draws a dashed centre line, so the fold can be lined up while framing instead of
discovered afterwards, and the hint under the shutter says what the mode does.

### What's fixed

#### The live outline holds still while the page does

Two descriptions of one still page — a loose quad around the whole sheet and a tight one around the
ink on it — trade places in the detector's ranking from frame to frame, and a border that hears only
the winner has to take every swap as a move. The measured recording shows where that ends: the
swapped-in answer is pinned to the frame's border, which the preview crops away, so the stroke
vanished from the screen rather than moving across it.

The detector now reports its whole shortlist, and that shortlist is weighed against the outline
already on screen, in units of the outline's own span. A candidate somewhere else is evidence that
*a* page is in view and nothing about where, so it refreshes the hold and leaves the border where it
is; it is believed only once the same description has been offered for the full hold, which a swap
never is, because the two descriptions are not the same one. A test replays the recorded sequence
against the figures the work was accepted on, and the disagreement rule is pinned in both directions.

#### The outline follows the page instead of stepping after it

Detection asked for a new outline every 150 ms, and the ease that moved the border to it finished in
120 — so the border arrived, sat still for 30 ms, and set off again. That pause is what made it read
as stepping after the page rather than following it.

Detection now runs ten times a second, and the move to a new position now takes 180 ms, longer than
the gap between detections, so the next detection arrives before the current move has finished and
the outline is never at rest while the page is moving. Nothing else about the border changed: the
same five density-independent pixel deadband, applied per corner, the same wait before it gives up
on a page, the same confidence gate, the same stroke.

#### Detect keeps the rotation you applied by hand

The automatic pass owned one rotation number, so every run either inherited your turn and could not
revise its own decision, or overwrote your turn to state a fresh one — which is why **Detect**
appeared to turn a page back. The two are separate facts decided at different moments, so they are
held apart: the turn the detector decided and the turns you asked for are carried separately and
added, and **Detect** revises only its own half. The outline follows the same split, so the border
stays on the physical edge it belongs to. (The known-issue note in the previous two releases is
removed.)

#### Pages can be swiped again

The page's pinch-and-pan detector sat inside the pager and consumed every drag it was handed, so the
pager underneath it never received one: a page could be opened but never left, and the counter stayed
on whichever page the document was opened at. The detector is now written by hand so it can decide
what is actually its own — a single finger at natural size is a page turn and is left alone, while a
pinch, or a drag while zoomed in, belongs to the page and is consumed. Zoom, pan and the snap back to
natural size behave as before.

#### The Batch chip and the mode chips say their state

The **Batch** chip is a toggle drawn as a coloured chip and the mode chips are a one-of-three choice
drawn the same way, so for anyone not reading colour they said nothing at all: tapping Batch
announced "Batch" whether the run went on or stopped after the shot. Both are now the controls they
look like — a switch and a radio group — so a screen reader reads the state off the control instead
of the pixel colour. Nothing about what a tap does changes.

#### The review overlay is closed, not backed out of

The batch review is drawn over the capture screen rather than inside a stack of screens, so its
arrow pointed at a screen that does not exist. It is now a cross, and it dismisses the review back to
the camera with the page kept.

### Also in this release

- A page's stored look, its deskew angle and a counter of how many times it has been re-rendered
  arrive with a database migration that runs in place. Existing documents, their pages, their
  filters, their crops and their text are untouched; nothing has to be set up or re-scanned.
- Every re-render of a page — a rotation, a filter change, an edit, an apply — now goes through one
  path that reads the page's geometry from the page and its look from the caller, which is what
  stops the two drifting apart.
- The suite is 267 unit tests in 28 classes, all runnable on a plain JVM, and it grew alongside the
  work: the look value and the mapping every render goes through, the rules that decide who
  **Apply to all** is offered to and which pages it touches, the composition of the detector's turn
  with yours, and the outline's disagreement rule.
- The work order and the specification for each change are no longer kept in the repository. They
  are the build's own working notes, rewritten every release; what a release changed is said here and
  in the README.

### Known issues

- **The live outline is found on a subsampled frame.** The preview's grayscale image is made small
  for detection by skipping pixels rather than averaging them, so the detector sees a slightly more
  aliased picture here than it does on a photograph. On a busy background that can cost the live
  border confidence that a still shot keeps.
- **A border can run off the screen.** The preview fills the screen by cropping the frame, so when
  the page reaches the frame's sides — which is what happens when it fills your view — the part of
  the border tracing those sides is drawn outside the visible area. It marks where the page really
  is, but on a tall phone it can read as two lines rather than a frame.
- Folder support is unreachable end to end. No code assigns a document to a folder — every document
  is created with a null folder — so the folder filter never appears at all.
- Rename works on one document at a time: with more than one selected the Rename action is not
  offered at all. Bulk delete is correct.
- Rotating a page does not invalidate the stored OCR line boxes, so the invisible text layer of a
  searchable PDF exported after a rotation can be placed against pixels that have since moved.
  Reading and searching are unaffected; running the recognition again stores fresh positions.
- `sweepCaptures`, the cleanup of stale capture files, is written but not called from anywhere.
