### What's fixed

#### The review's buttons are clear of the system bars

The batch review is drawn over the capture screen rather than as a screen of its own, so it inherits
nothing from the camera's layout and has to keep clear of the system bars by itself. It did not: it
put its own strips at the edges of the window.

Measured on a 1080x2400 phone with three-button navigation, where the status bar ends at 134 px and
the navigation bar occupies the last 135: the review's **Close** was drawn at 68–136, inside the
status bar and level with the clock, and **Re-take** at 2259–2316, entirely inside the navigation
bar — so the system could take a tap aimed at either of them. On the camera screen underneath, the
same **Close** sits at 168–236, clear of the clock.

The review's top strip now takes the status-bar inset and its bottom strip the navigation-bar inset,
by the rule the camera, the document, the editor and the viewer already follow: the picture still
fills the screen behind the bars, and only the controls move in. The page image takes both insets as
well as the clearance it keeps from the controls above and below it, so the page is not drawn under
the clock or under the system buttons either.

Measured again on the same phone: **Close** at 168–236 — the strip the camera's own **Close**
occupies — and **Re-take** at 2124–2181, in the same strip as the page-step arrows at 2119–2187. All
of them are above the navigation bar.

### Also in this release

- **Nothing else changes.** The same shot, the same crop, the same filters, the same automatic
  shutter and the same framing outline. No setting appears or disappears, and everything the review
  does — stepping, rotating, turning over, re-taking — is unchanged.
- The suite is still 267 unit tests in 28 classes. The review is a Compose overlay with no state of
  its own, so this change is pinned by measurement on the device rather than by a test, and the
  figures above are that measurement.
- The work order and the specification for a release are our own working notes and are not kept in
  the repository; what a release changed is said here, in the README and in the CHANGELOG.

### Known issues

- **The live outline is found on a subsampled frame.** The preview's grayscale image is made small
  for detection by skipping pixels rather than averaging them, so the detector sees a slightly more
  aliased picture here than it does on a photograph. On a busy background that can cost the live
  border confidence that a still shot keeps.
- **A border can run off the screen.** The preview fills the screen by cropping the frame, so when
  the page reaches the frame's sides — which is what happens when it fills your view — the part of
  the border tracing those sides is drawn outside the visible area. It marks where the page really
  is, but on a tall phone it can read as two lines rather than a frame.
- Folder support is unreachable end to end. No code assigns a document to a folder — every document
  is created with a null folder — so the folder filter never appears at all.
- Rename works on one document at a time: with more than one selected the Rename action is not
  offered at all. Bulk delete is correct.
- Rotating a page does not invalidate the stored OCR line boxes, so the invisible text layer of a
  searchable PDF exported after a rotation can be placed against pixels that have since moved.
  Reading and searching are unaffected; running the recognition again stores fresh positions.
- `sweepCaptures`, the cleanup of stale capture files, is written but not called from anywhere.
