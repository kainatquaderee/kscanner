### What's fixed

#### The automatic shutter fires on a page you are holding

The automatic shutter had never fired by itself. The gate that decides when to fire was reading the
**whole frame** — the desk, the room, the dark table the page is lying on, and the softened edges of
the preview — and holding a page still and in focus does not make any of that good. At the
resolution the live analyser actually reads, a page of prose filling the view scored sharpness 0.0212
against the 0.10 the gate demanded before it would fire, so the reading that mattered never once
reached *ready*, however long the page was held.

The gate now reads the **page**, not the frame: the same measurements — brightness, ink, glare,
evenness and sharpness — taken over the pixels inside the outline the detector is following, and
over the whole frame only when there is no page to follow. The paper is the thing being photographed,
so it is the thing the shutter should read. On the same held page the two readings are now:

| | the frame | the page region |
| --- | --- | --- |
| brightness | 166.4 | 223.6 |
| ink on it | 0.213 | 0.117 |
| sharpness | 0.0212 — *Hold still* | 0.0177 — **Ready** |

Three failures fall out with it, and they are the reason the page region had to be measured rather
than the frame tightened:

- **A page on a dark table.** A sheet on a desk dark enough that the frame reads *Not enough light*
  (brightness 54 to 61) reads **Ready** on the page — the paper is lit, the table is not, and only
  one of the two is the photograph. The desktop can be taken right down without moving the paper's
  own reading at all.
- **A page beside a bright window.** The window leans on two of the frame's quadrants and on none of
  the page's. Judged as a frame the imbalance is 0.840, well past the 0.42 that says *Even out the
  light*; judged over the paper it is 0.063. A shadow actually across the paper still reads 0.495 and
  still asks for even light, and a lamp held to one side still reads 0.394 — under the line, where it
  belongs.
- **A sparse form.** A sheet with four lines on it carries ink 0.018 over the region where the desk
  alone carries 0.150, so it is read as a document; a blank sheet still reads *Point at a document*.

The page's own sharpness is judged against a line of its own (0.0012), fitted between a page in focus
— 0.0177 for a page of prose, 0.0075 for a boxed table, 0.0023 for a mostly blank four-line form —
and the same pages blurred by the smallest blur there is, 0.0007 or less. The frame's own line (0.055)
is left where it was, for the still-photo path, which reads a full-resolution capture that a live
frame is not.

#### The shutter waits for the page to settle

The gate used to count five consecutive good **analysis frames**, and to require twice the clarity of
the on-screen advice before it would fire. Neither was the question worth asking. Frames are not
something anyone chose — a new outline only arrives about ten times a second, so the frames between
two detections have nothing new to say about where the page is — and a whole frame's clarity is a
reading of the desk as much as of the paper.

It now counts five consecutive stable **detections**, and "stable" is measured against the outline
that started the run rather than against whatever the previous detection was, so a page drifting
slowly across the preview no longer resets the run every few detections and never fires; a step to a
different page still starts a fresh run. Five detections is about half a second of holding still,
after which the shutter stays shut for about a second so the next page has time to arrive. The
doubled clarity demand is gone: the page region's own answer is the question now, so a shot is no
longer refused for being borderline by a line drawn for something else.

The ring around the shutter fills with the run, so what it shows is how far the page has settled.

### Also in this release

- **Nothing else changes.** The same framing outline, the same crop, the same filters, the same
  editor. No setting appears or disappears, and the automatic shutter keeps its on/off control.
- The suite is 281 unit tests in 29 classes (from 272 in 28), runnable on a plain JVM. The new
  coverage is the page region — a page over a dark desk, a form, a page beside a window, a sheet with
  no rim read as detail — and the gate: it fires on the detection that completes a stable run, a slow
  drift does not break the run but a step does, a page that leaves restarts it, and a page whose
  region is dark or glaring does not fire. The figures quoted above are the readings those fixtures
  give, pinned by assertions, so a change that moves one says so.
- The work order and the specification for a change are our own working notes and are not kept in the
  repository; what a release changed is said here and in the CHANGELOG.

### Known issues

- **The live outline is found on a subsampled frame.** The preview's grayscale image is made small for
  detection by skipping pixels rather than averaging them, so the detector sees a slightly more
  aliased picture here than it does on a photograph. On a busy background that can cost the live
  border confidence that a still shot keeps.
- **A border can run off the screen.** The preview fills the screen by cropping the frame, so when the
  page reaches the frame's sides — which is what happens when it fills your view — the part of the
  border tracing those sides is drawn outside the visible area. It marks where the page really is, but
  on a tall phone it can read as two lines rather than a frame.
- **A failed detection still keeps the whole frame.** When the detector finds no page in a still
  shot, the capture is kept uncropped rather than guessed at. The page-region measurement here is not
  yet a fallback for that; it is the next change.
- Folder support is unreachable end to end. No code assigns a document to a folder — every document is
  created with a null folder — so the folder filter never appears at all.
- Rename works on one document at a time: with more than one selected the Rename action is not offered
  at all. Bulk delete is correct.
- Rotating a page does not invalidate the stored OCR line boxes, so the invisible text layer of a
  searchable PDF exported after a rotation can be placed against pixels that have since moved.
  Reading and searching are unaffected; running the recognition again stores fresh positions.
- `sweepCaptures`, the cleanup of stale capture files, is written but not called from anywhere.
